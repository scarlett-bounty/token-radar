How the model works

Every number on this board is derived from the sealed snapshot's own figures. No protocol name is ever special-cased: the same function scores every row.

  1. Peer multiple. For each category, the median market-cap / TVL of its live-token protocols — the multiple the market already pays for a token against the value locked in its protocol — shrunk toward the global median when the category has few live peers, and read as the global median when the category has fewer than three live peers at all: one or two peers cannot price a category. The multiple is clamped to 0.05 – 0.80.
  2. Base. TVL × peer multiple.
  3. Growth. × (1 + 0.30 × tanh(7-day TVL change / 40)), change clamped to −50% … +100%. No reported change reads as neutral.
  4. Maturity. × (0.85 + 0.30 × min(age in days, 1460) / 1460). A protocol that has run up to four years with no token earns up to a 15% premium; an unknown listing date reads as 365 days.
  5. Breadth. × (1 + 0.02 × min(chains − 1, 4)). A small premium for running on more chains.

Implied value = base × growth × maturity × breadth, rounded to whole dollars.

What the board covers

The watchlist is the floor, never the ceiling: the board ranks all 40 watchlist protocols plus every other rankable pre-token protocol below the $50M floor — pre-token, not an exchange, not a bridge, liquid-staking or restaking product, not a versioned pool, not a wrapped or staked product of a token that already trades. Above the floor the radar follows the watchlist exactly, because the house's watchlist rule also reads each protocol's parent record, a field the snapshot does not carry: the other above-floor protocols are arms of another protocol, not standalone launches. Live-token protocols are kept apart on the Live tokens tab with the market's own values (market cap), never mixed into the ranked board.

Say a protocol records no token, never that it has none: a protocol on the list may still hold a token its record does not carry. The board states an implied value; it does not predict whether or when a token is issued.
